# Pylons Changelog

Notable changes to the Pylons format and `pylon` CLI.

## 2026-11-27

- Three borrowed mechanics from a survey of agentmemory (rohitg00/agentmemory), ported to the deterministic spine: `pylon brief` grew bounded session-start sections (header, fetch state, in-flight plans and proposals, a per-zone census) under a `--budget` line cap with fixed priority and an explicit hidden-lines marker; `pylon import` adopts existing markdown by grafting the type template's frontmatter onto a verbatim body (dry-run default, `--write` applies, valid frontmatter skips, unparseable frontmatter refuses); `pylon doctor` gained a corpus-size advisory (DOCTOR013) that names the doc count, total bytes, and the largest documents once a ledger crosses 120 docs or 1 MB. `scripts/bench.sh` takes dated synthetic-scale latency receipts under `docs/benchmarks/` (first receipt: 1000 docs — map 33 ms, search 40 ms, brief 34 ms, median of 3), because a performance claim without a rerunnable receipt is prose.
- Recall hygiene closes the loop the decision records already promise: `PYLON066` flags a doc that declares `superseded_by` while still outside an `archive/` folder, because search and map serve non-archived docs and the dead conclusion would keep answering queries. `PYLON067` makes contract claims single-owner: the same `kind` and `id` claimed by two package docs, or twice in one doc, is FORCED, while pending entries (candidates, not owners) and archived claimants (history) stay exempt. On the Atlas dogfood ledger the new rule surfaced six real double-claims on first run; each resolved to one code-verified owner.
- A peer review caught a data-loss path in `doctor --fix`: bootstrapping `manifests/product.json` from disk mislabeled user edits and ledger-local files as release state, and the next self-update silently removed what it had recorded as release-dropped. The repair is gone; DOCTOR011 points at one self-update run or a reinstall, because only a real release can establish the record.
- `doctor --fix` keeps its hands off other tools and half-broken state: a foreign `core.hooksPath` is reported, never taken over; a nested ledger gets an info finding instead of an unfixable error; one failed repair no longer silently skips the rest (failures are collected and exit 1); a corrupt baseline is rewritten with a `.bak` copy and a newer-version baseline is never downgraded; an unreadable pylons.yaml blocks manifest regeneration; `exclude:` globs stay silent.
- `pylon doctor --format json` is clean: stdout is pure JSON with `[]` for healthy, prose and repair lines on stderr.
- `pylon doctor` agrees with the pre-push gate on `generate:`: an absent list maintains `vocabulary` too.
- `scripts/release.sh` runs the wire-level gates on the product ledger, and `install.sh --bin-only` lands LICENSE and NOTICE beside the binary.
- `pylon doctor [--fix]` audits ledger structure: missing product files, zone entry docs, archive keepers, empty product trees, dead project paths, hook wiring, `bin/pylon`, generated-manifest parsability and staleness, the product record, and the baseline. `--fix` repairs the fixable class (writes entry docs and keepers, wires hooks, regenerates manifests, records a legacy product state) and leaves semantic calls to the user. Doctor checks the structure lint assumes; content rules stay with lint.
- A dedicated update guide: `docs/UPDATING.md` covers the three update paths, the three-way file merge, drift review with the exit-4 contract, and legacy ledgers; INSTALL.md and the shipped `adopting.md` point at it.
- The installer reports drift as success with a review note: `self-update` exits `4` when files carried your edits (previously `1`, indistinguishable from a real failure), so the piped installer no longer claims the update failed after it applied, and it no longer announces a `_pylons-backup/` directory when nothing needed backing up.
- Ledger templates declare the frontmatter schema their docs are validated against: `pylon lint` unions the keys found in `templates/*.md` into the built-in registry, so a ledger-local workflow key no longer waits for an engine release to stop firing PYLON064. The key lives exactly while its template does — deleting the template restores the advisory — and generated manifests keep mirroring only the engine's built-in schema.

## 2026-11-26

- Gate review passes honor the accepted-debt baseline: the commit hook ran the plan and postmortem reviews on staged files outside `ApplyBaseline`, so debt accepted in `manifests/baseline.json` passed `pylon lint` and still blocked the commit (observed live: a proposal with twenty-four accepted findings sailed through lint and died at pre-commit). Review findings now flow through the same baseline as lint, and the staged-path predicates moved into the rules package (`PlanReviewPath`, `QuirkReviewPath`) so the gate and lint cannot drift apart.
- STE100 counts words, not tokens: symbol-only tokens (`+`, `=`) and the structured sizing tails ledgers append to task bullets (`- dev 4 + qa 0 + review 1 = **5**`) no longer inflate sentence length, so fitting the twenty-word bullet limit no longer forces deleting real content from plan tasks. Prose rules are unchanged: long sentences still flag, and a tail never rescues genuinely long prose. The finding preview keeps its old format, so baseline keys recorded by earlier engines still match; within one line the flag can move to a later sentence when an earlier one drops under the limit, and a ledger refreshes that with `pylon lint --update-baseline`.
- `exclude:` now keeps its full promise: pylons.yaml exclusion globs were honored by the lint walk but ignored by the corpus indexer, so an excluded folder stayed visible in `map`, `search`, and `status` and "never linted and never indexed" was half true. The indexer loads the manifest and applies the same globs, so one pattern (`atlas/**`) takes a whole folder out of every surface.
- Lint reviews `plans/proposals/` documents regardless of status, matching the commit gate's path-based selection: the gate reviewed every staged doc there while lint only reviewed `status: proposed`, so a finding the gate blocked on could never be recorded through `pylon lint --update-baseline` and blocked every commit forever. The review now keys off one shared predicate (`PlanReviewPath`), and `plans/regular.md` style docs outside the review zones stay unreviewed.
- The commit gate's review passes skip documents the ledger excluded through `pylons.yaml`: lint already honored the exclude list, but the plan and postmortem review loops did not, so an excluded zone turned back into a commit blocker that no baseline entry could ever cover (excluded docs generate no lint findings).

- The frontmatter key registry covers the workflow keys the Atlas ledger templates document: `asana` ticket links on package, convention, plan, decision, and domain-entity docs; `package` on references; `persona` on the new user-guide and configuration types; `anti_patterns` on conventions; `review_note` on plans. PYLON064 no longer fires on roughly three hundred documents whose keys the ledger's own templates bless, and `pylon new` can start user-guide and configuration docs. Quirk zone entry guides (`AGENTS.md`) no longer trip the 30-day guard clock: they are references, not quirks.

## 2026-11-25

- New `pylon status <doc-path> <new-status>` command performs a status transition deterministically: the status validates against the zone's closed set, unmet closing obligations refuse fail-closed naming the rule (PYLON009 `artifact:` for shipped plans, PYLON065 `## State` for paused plans, PYLON031 sections for closed investigations, PYLON010 naming for accepted decisions), an existing move target refuses without overwriting, the frontmatter `status:` and `updated:` lines patch in place, and the file renames when the new status places it elsewhere (archive moves, proposal promotions, and moves back into `proposals/`). Zone entry guides, symlinks, and docs without a status line refuse; CRLF files patch correctly; a body `updated:` line is never rewritten.
- `pylons/manifests/vocabulary.json` is now generated, not hand-maintained: `pylon manifest vocabulary` compiles it from the tables the binary enforces (status sets, contract kinds with their id-form documentation, the per-type key registry, protected owners with severities, and the closed field value sets), and the pre-push gate fails when the mirror drifts from the binary, unless the ledger opts out through `generate:`. Generated output no longer HTML-escapes angle brackets, so `rules.json` fix hints and the kind id forms read as literal text. The regeneration also corrected one stale claim the hand-maintained copy carried: the quirk `guard:` value set is enforced by `PYLON028`, which the mirror now states.
- Plans gained a `paused` status. A paused plan is started work on hold, and it cannot walk away silently: `PYLON065` forces a `## State` section naming the resume point — what is done, the next step, any blocker — so the next session reads where work stopped. Contract checks keep their accepted and in-progress scope; paused work is not held to live contracts until it resumes.
- Class-only namespaced `php-symbol` ids resolve: an id shaped `file.php::Vendor\\Namespace\\Class` now resolves against the declaring file's namespace statement without a `::method` part, where the namespace branch previously ran only for two-part `Class::method` ids and every class-only id fell to a bare-symbol matcher that can never match a backslashed name, failing foreign exposes with `declaration not found`. The method-form branch shares one namespace-match helper with the new class-only branch, so the two engines cannot disagree on what a declaration match means. The adoption manual grew the foreign package manifest migration recipe (Atlas is the worked example: an eleven-field dict mapped field by field onto pylons.yaml projects and package-doc frontmatter), and the repository root operating guide carries verified build, test, lint, and release commands.
- The repository now separates engine from ledger: the whole ledger payload (zones, machine manifests, templates, protocols, extensions, reference pages, license files) lives in `pylons/`, the engine source stays in `cli/` beside `scripts/` and the manual in `docs/`. A release archives `pylons/` verbatim, so what `install.sh` places in a fresh ledger is exactly what the folder holds, and the product manifest is generated ledger-relative. New files inside `pylons/` (including `pylons-docs/`) ship to installed ledgers on update; the manual and the example ledger stay in the source repository. Ledger discovery resolves in three steps: an explicit `--pylons`, a walk up from the working directory, then the binary's own home, so `pylons/bin/pylon brief` works from the parent project root. The installer asks for the ledger folder name (default `pylons`) when run interactively, creates the ledger with its own remote-less git repository, refuses to touch an existing repository inside the target, and updates an existing pylon in place without touching user files. Gate hooks stay an installed-ledger feature: a ledger that is not the repository root cannot wire them, so a nested dev ledger runs `pylon lint --pylons pylons` instead.

## 2026-11-24

- Quirk sources pinned with `repo://alias@branch` fire only on that branch: quirk guardrails, `context --slice`, and the ripple advisory compare the pin against the checked-out branch read from the git HEAD ref. A detached HEAD or a missing repository keeps a pinned source silent; a branch-less source behaves as before. A branch name cannot contain a slash. Slice matching stays alias-scoped by design: the slice orients on the whole component, guardrails are path-scoped.
- Parity edge cases closed: maven pom identity reads the tag stream, so a one-line `<project>` resolves and a commented-out or dependency-block coordinate never stands in. Kotlin imports accept the trailing-semicolon form. Postgres dollar-quoted strings (`$$...$$`, `$tag$...$tag$`) are masked before comment stripping by a scanner that walks comments and quoted strings first: a `$` inside a comment or a string is text, a `$` after an identifier character is an identifier tail, and only a token-boundary opener masks, so a `$` pair outside a real dollar quote can no longer hide a declaration.
- New files in `protocols/` ship to installed ledgers on update: the whole tree joins `productTrees`, so a new protocol document reaches existing ledgers on the next release instead of waiting for a fresh install. The two shipped protocol docs keep a release-time required-file guard, so a checkout missing them still fails the build.
- The command and flag dictionary is canonical in `USAGE.md` alone; `FEATURES.md` keeps the feature cards, the loop, and the exit codes, and points at the dictionary. A new command or flag edits one table. The rows the consolidation would have dropped (aroma query flags, `persisted_key:` and `verified_by:`, the gate's `PYLON_HOOKS_OPTIONAL` opt-out, and the exit-code summary) moved into `USAGE.md`.
- The built-in parity set grows from eight to fourteen languages: c, cpp, java, kotlin, dart, and sql join go, rust, php, typescript, javascript, python, csharp, and ruby. States set-checks ship in-process for the six new languages. C enumerators and C++ `enum class` take an optional backing type. Java constants take constructor arguments and end at the constant-list semicolon. Kotlin takes `enum class` entries one per line. Dart takes plain enums and enhanced enums without constructor arguments. SQL takes Postgres `CREATE TYPE ... AS ENUM` on one line or one value per line, and `ALTER TYPE ... ADD VALUE` folds in. Each shape fails closed on what it cannot read, never silently drops a member. MySQL column `ENUM(...)` has no extractor: it is a column option, not a named set.
- The dependency graph gains import extraction for java (qualified maven pom.xml coordinates: the parent block and dependency blocks never stand in; the bare artifact name is not an identity), kotlin (gradle root name and group, groovy and kotlin dialects, both quote styles, commented lines ignored), and dart (pubspec name; `package:` and `dart:` URIs, exports included). Java on-demand wildcard imports yield no edge: they name no single project. C and C++ `#include` extraction was dropped: a header include names a file, not a package, and the languages carry no package identity, so edges could never resolve.
- A braceless enum reference (a C field declaration or a C++ forward declaration) and a function signature or parameter list mentioning the type are skipped during parity extraction, so they can no longer poison the real definition. Kotlin primary-constructor enums parse. A member parse that reads zero members fails closed, as does a comment strip inside a string literal: comment markers inside quoted values survive on every language.
- cpp claims the shared `.h` header over c on the implicit extensions path; a project enabling only c keeps `.h`. An explicit parity spec claiming `.h` from both is a config error, like `.js` for typescript and javascript. A profile re-listing an extension its language already owns is no longer a self-conflict. The extension-conflict error names profiles in sorted order, deterministically.

## 2026-11-23

- `pylon review utility [--prune] [--promote]` lands the knowledge-utility roadmap item. The corpus declares citations with `<!-- pylon:referenced-doc: <path>.md -->` markers (one per use, value is the ledger-relative path); the engine records one injection every time `pylon context` or `pylon context --slice` delivers a document, into `pylon-utility.json` in the git dir beside the sync state. The score is citations over injections with a 30-day half-life, so stale history stops counting. `--prune` moves quirks delivered on at least two distinct days whose uncited weighted mass clears 3.0 to `quirks/archive/`, never overwriting an existing archive entry; `--promote` writes one convention proposal stub per document cited three or more times from two or more files, named from the full ledger path so same-stem documents never collide. Both need evidence: a fresh clone carries no telemetry, absence of evidence never prunes, one heavy day is not repeated use, and deleted documents never score. The agent session loop and the scaffolded ledger AGENTS.md now carry the citation step. The product and reference trees (`templates/`, `protocols/`, `pylons/`, and the engine's own dirs), fenced code blocks (backtick and tilde), and README/AGENTS/CONTEXT documents are excluded from the citation scan, because marker examples there are documentation, not use. Plain `pylon context` surfaces quirk guardrails on the human surface: quirks whose `repo://` sources cover a target (exact path or directory ancestor, project-attributed targets only) print in the human output and count as injections, closing the gap between the context card's promise and the engine. Telemetry records are validated on read: a malformed record fails the command instead of reaching the filesystem, and scoring is day-granular so the hour of the run cannot flip a threshold.

- `pylon check --plan <plan> <paths...>` fixes the self-collision: `check` reported `FORCED` on the paths that the caller's own active plan edits, so the author of a plan could not pass on its scope and had to ignore a stop signal. The flag names one accepted or in-progress plan. Its `contract.editing` and `contract.unstable` sets no longer stop the caller, while every other plan, every `protected:` glob, and every ripple finding still reports. Without the flag nothing changes. `pylon context <paths...>` takes the same flag. A name that is missing, outside the ledger, not a plan, or not active is a usage error (exit 2), never a silent exemption. The agent protocol re-checks with `--plan` after it takes a plan.

- The self-update contract closed its hostile-release holes: a release manifest may only write product-layer paths, every platform binary is pinned by hash (release.sh passes all five cross builds, and the updater refuses an unpinned or mismatched binary), staged trees may not smuggle symlinks, and same-version re-releases get their own backup directories. Install refuses before it wires anything when `bin/pylon` cannot run, warns about legacy `.git/hooks` scripts that `core.hooksPath` benches, and replaces a symlinked hook with a real file on takeover. The gate's pre-commit drift stage honors `generate: []` per manifest kind and can no longer die on missing manifest files. Parity extractors gained language-true comment handling (rust attributes no longer swallow cases), fail-closed canonical-shape messages, and the annotations summary escapes rule ids from parsed input. Test fixtures now locate the repo root by walking up, four previously untested rules carry pinning tests, and the usage text, exit-code table, and adoption docs state the real behavior.

- TypeScript joins the parity transition profiles: the canonical shape is the nested switch reducer (outer switch on the state, inner switches on the event, string-literal returns) under the `// pylon:machine` directive. Absorbs, default arms, and throw guards declare no triples; computed returns, casts, single-line case bodies, and other reducer logic fail closed.

## 2026-11-20

`pylon aroma` ships structural code similarity as a top-level subcommand: given changed lines, a snippet, or a diff, it finds the corpus methods whose code structurally resembles the query and returns the code they share, zero model calls, advisory only. The algorithm is the Aroma paper (OOPSLA 2019) ported from its reference implementation, pinned by differential goldens generated from that reference, with a stdlib-parser Go front end and a recall benchmark. The corpus defaults to the ledger's registered projects, else `--corpus`. Review hardening closed its findings batch: corpus roots are labeled so several projects cannot collide and every query input resolves inside its owning root, snippet, diff, and stdin reads run through one bounded regular-file reader, the Go front end stops reading selector fields, literal keys, and labels as locals, explicit flag zeros survive parsing, `--help` works after the subcommand, and an empty corpus exits 2, so the command never exits 1. Two more roadmap items shipped: `pylon review release-surface --pinned-releases <dir> [--base <ref>]` blocks when a pinned deployment consumes a public surface (symbol, route, or cli contracts) that is removed or changed against the pinned release tag, with unknown pins, missing tags, and unevaluated pins failing closed or advisory; and `pylon context --diff-since <ref> [--manifest]` reports declared surfaces the diff touched whose docs did not move in the same commit set, report-only, with the friction-scored quirk capture left to the agent harness per the not-adopted list.
