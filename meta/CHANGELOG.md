# Pylons Changelog

Notable changes to the Pylons format and `pylon` CLI.

## 2026-11-21

Transition parity ships: `lint --parity` now checks whole machines, not just state sets. A domain entity declares each lifecycle as one entry of a `machines:` frontmatter list carrying its id, state set, transition triples, mandatory initial and terminal sets, code pointers, and an `on_unevaluated` knob that upgrades the not-evaluated advisory to an error. Doc-only checks (malformed declarations, repo-wide duplicate machine ids, unknown states in triples, unreachable and dead states, duplicate from-event pairs) run without `--parity`, so a declared machine is checked before its code side is bound. The code side compares extracted transition triples in both directions: the Go profile parses the marked nested map literal with the stdlib parser, the php profile the marked class-constant nested array of quoted case values, and the rust profile the `(State::A, Event::B) => State::C` match arms, with duplicate map keys surviving for the duplicate rule and wildcard fallthrough arms never counting as triples. Extraction rides the new declarative parity spec: a closed-schema `parity:` section in `manifests/pylons.yaml` (schema at `manifests/parity.json`) binds languages to built-in profiles or external plugins with explicit `use:` bindings, per-project overrides, and extension-ownership validation, so unknown keys, unknown builtins, and disabled external plugins are hard config errors while an absent section keeps the implicit builtin bindings. External plugins answer the states and transitions ops over the existing JSON protocol with the engine sending bounded source text, and a reference plugin under `testdata/plugins` demonstrates the wire contract. `persisted_key:` turns on a scan for direct writes of the machine's state outside the machine surface (advisory, outside the ratchet budget), `verified_by:` names the table tests that prove purity and throw-on-invalid, and `pylon brief` reports the ledger's machine count. New rules `PYLON053` through `PYLON059`. The ledger ships clean for third-party users: no dogfood convention content lives in the product workspace, so the machine discipline moved into the parity spec doc and the merge-danger PR template left the repository. The closed frontmatter vocabulary became a machine-readable registry at `manifests/vocabulary.json` with its annotated page in `meta/docs`, the installer moved under `scripts/`, and `meta/docs/` carries the product's own reference material. Every CLI walker now ignores directories whose name starts with `_`, so example and scratch space (reference plugins under `extensions/_examples/`) ships with the pylon without ever acting as live content. Adoption round: the rust parity profile reads event-less adjacency machines (`State::A => &[State::B]`, event optional on declared triples, terminal sets optional) and its arm parser handles or-patterns, path prefixes, wrapped values, and fails closed on arms it cannot read; projects registered at a subdirectory of a workspace repo keep their configured `ref:`; `pylon install` refuses when every gate hook is foreign; a `generate:` list disables gate maintenance of either generated manifest; a `schemes:` list makes the ledger's own URI schemes checkable; an `exclude:` glob list removes paths from the engine and a `manifests/baseline.json` of accepted FORCED findings lets known debt stop blocking while anything new still fails (`lint --update-baseline` regenerates); and the release ships a product manifest so `pylon self-update` can update an installed pylon in place: staged files verify first, unmodified product files are replaced, user edits land as `.pylons-new` copies, user files are never touched, replacements are backed up under `_pylons-backup/`, and the binary swaps last, with `scripts/install.sh` driving the update instead of refusing an existing pylon. YAGNI pass: the flows zone is gone (diagrams belong beside the code they describe) and audits merged into investigations as a document type sharing the zone and its archive, with the audit rules intact. Every shipped example and template now names its owner Pylons. Shipped examples: `_examples/ledger/` is a miniature ledger (machine, plan, quirk, and the Go code they check) and `extensions/_examples/pylon-ext-parity` is a runnable parity plugin, both guarded by engine tests and shipped in the product manifest. An unset project `ref:` now means working-tree reads; the old silent default of `main` resolved contracts against the committed tree, so a lint before commit checked stale code and uncommitted files "did not exist".

Same day, the machine-contract batch: provider-shaped credentials fail lint (PYLON060, advisory assignment shapes PYLON061), both exempt from baseline suppression; `pylon review gate-surface` blocks diffs touching the checker's own surfaces (PYLON062, PYLON063); frontmatter decoding went strict with anchors, aliases, merge keys, and custom tags failing closed and unknown keys inside closed payloads blocking (PYLON001 names the line), while unknown top-level keys stay advisory (PYLON064); the per-type key registry landed in manifests/vocabulary.json under frontmatter_keys with a mirror test; the findings and SARIF output shapes gained schema tests; the review-brief findings section states the severity rubric; meta/docs/machine-contract.md documents what machines read and how schemas move.

Same day, the peer-review pass closed on the batch: the baseline exemption now holds wherever the baseline is applied, not only where entries are written; the gate knob scan reads context, so an added item under an existing `exclude:` fires, renamed gate surfaces are caught through a per-commit union, `--ci` turns an unreadable base into a failure, and the declared-schema `templates/` joined the gate surfaces; the strict contract-entry list knows `external`; aliases referencing key anchors fail closed; the known-key set carries the engine-read `links` and `supersedes` on every type; frontmatter finding lines are file-relative; and the secret scan reads raw content even when frontmatter fails, with a `pylons-allow-secret` line marker, a word boundary on provider prefixes, and a digit requirement on assignment shapes.

Same day, the adoption round: `manifests/baseline.json` is a readable debt ledger (entries carry the rule, file, message, and a count, so repeated findings are judged by count instead of collapsing into one hash, and a foreign version is rejected loudly); `decision_prefix:` names accepted-decision files, so a ledger with `A0001` style names keeps them; `pylon gate pre-commit|pre-push` moves all gate logic into the compiled engine behind thin hook shims, `pylon install --force` keeps the old hooks as `.bak` copies, and the foreign-hook refusal names the chain line; `scripts/install.sh --bin-only .` installs the binary into an existing directory; the rust parity extractor reads rustfmt-wrapped adjacency arms and fails closed on guarded arms; `meta/docs/adopting.md` is the knob-by-knob adoption path; the baseline banner moved to stderr so JSON and SARIF output stays parseable, and lint rejects stray positionals.

## 2026-11-20

`pylon aroma` ships structural code similarity as a top-level subcommand: given changed lines, a snippet, or a diff, it finds the corpus methods whose code structurally resembles the query and returns the code they share, zero model calls, advisory only. The algorithm is the Aroma paper (OOPSLA 2019) ported from its reference implementation, pinned by differential goldens generated from that reference, with a stdlib-parser Go front end and a recall benchmark. The corpus defaults to the ledger's registered projects, else `--corpus`. Review hardening closed its findings batch: corpus roots are labeled so several projects cannot collide and every query input resolves inside its owning root, snippet, diff, and stdin reads run through one bounded regular-file reader, the Go front end stops reading selector fields, literal keys, and labels as locals, explicit flag zeros survive parsing, `--help` works after the subcommand, and an empty corpus exits 2, so the command never exits 1. Two more roadmap items shipped: `pylon review release-surface --pinned-releases <dir> [--base <ref>]` blocks when a pinned deployment consumes a public surface (symbol, route, or cli contracts) that is removed or changed against the pinned release tag, with unknown pins, missing tags, and unevaluated pins failing closed or advisory; and `pylon context --diff-since <ref> [--manifest]` reports declared surfaces the diff touched whose docs did not move in the same commit set, report-only, with the friction-scored quirk capture left to the agent harness per the not-adopted list.

Roadmap build-out, round 2. `pylon lint` gains `PYLON043`: files inside a registered project that import another registered project not declared in the owning package's `depends_on:` fire an advisory, backed by import extraction for go, typescript, python, rust, and php. `pylon check` names the ripple: plans and packages declaring the same contract id, quirks anchored to the same file, and domain terms named in the source (`PYLON044`). Plans gain the opt-in vertical-slice flavor: `slice: true` demands a behavior contract and a test surface (`PYLON045`), and declared `scenarios:` with `covers:` prove behavior contracts (`PYLON046`). `pylon context --slice <plan>` prints only that slice's contracts, resolved surfaces, linked quirks, and domain terms. `pylon protocol agent` ships the canonical agent session loop as a compiled protocol beside `reflect`. Same day: import-boundary matching hardened (alias-vs-package ownership, longest-prefix identity match, collision and nested-root ambiguity skipped, go parsed with the stdlib parser, python identities only for real packages, per-target dedupe, manifest reads lstat-bounded, `PYLON043` exempt from the ratchet budget); ripple gained glob-contract matching, a package-status filter, and real KB-doc anchors; slice rules gate on accepted/in-progress plans only and treat a covers-only scenario as no coverage; a plan document whose frontmatter cannot parse now fails loudly instead of silently skipping its rules. Two more roadmap items shipped: `pylon review merge-danger --body <file|-> [--base <ref>]` gates the required `Merge danger: <one-way|two-way> | blast radius: <scope>` body line (conventions/pr-template.md) against the closed door vocabulary and derives the minimum door from schema contract changes in the diff, blocking any downgrade; and `pylon sync --detached` runs a detached background fetch when the last one is over an hour old, applies fast-forward-only updates on a clean tree, records the fetch state in `.git/pylon-sync.json`, and surfaces `FETCH-FAILED <time>` through `brief`; the fetch state race, git worktree state paths, and the fast-forward guard (main only, strict ancestor) closed in the same pass. Two more shipped the same day: `pylon context --graph <package> [--depth N]` reports declared `depends_on` against the actual import edges the import-boundary extractor finds across registered projects, marking undeclared edges and unused dependencies, report-only; and `pylon review annotations --from <file|->` converts lint findings (SARIF or JSON) into GitHub Check annotations plus a summary comment body, blocking errors only and capped at 50, so the CI workflow posts inline PR feedback from pylon output. A third shipped the same pass: `pylon lint --parity` runs opt-in declared-vs-code set checks, comparing a domain entity's `states:` list against the backed enum at its `states_symbol` pointer (backing values when every case carries a literal, else case identifiers) with count and state mismatch as errors and an unresolvable enum failing closed as an advisory, plus route exposes checked against mentions in the mapped project source as an advisory. A peer review closed the same day hardened the extractors: blocks are found by delimiter matching so a later block in the same file is reachable, a case line the extractor cannot read fails closed as an advisory, trailing comments and single-quoted values parse, and `--parity` with `--doc-only` warns instead of silently doing nothing.

Hardening round. Project matching is deterministic for nested registered roots. Config errors surface instead of silently degrading output. All git subprocesses run under a 10-second budget. Symbol contracts match on word boundaries. Contracts whose components do not map to a registered project now fail instead of skipping. A configured git ref that does not resolve fails closed instead of falling back to the working tree. `pylon install` refuses a pylon below the repository root, detects another tool's `core.hooksPath` (override with `--force`), and reports hooks that drifted from the shipped assets. Gate hooks fail closed when no `pylon` binary is found; `PYLON_HOOKS_OPTIONAL=1` restores the old soft skip. `staleness --fix` patches frontmatter only. SARIF is rejected on commands that cannot render it; `pylon brief` without a pylon root exits 3. A one-line installer (`install.sh`) downloads a release into a project as a fresh pylon with its own git repository, verifies checksums, and wires the gate hooks; releases carry optimized per-platform binaries (`-s -w`, `CGO_ENABLED=0`, `-trimpath`) plus the skeleton and checksums, and `pylon --version` reports the release. The installed unit is now called a pylon: a plain-text map of the platform with a deterministic checker, replacing the working term knowledge base.

Roadmap build-out. Every lint finding now carries a remediation line sourced from the rule catalog (human, json, and sarif). Domain entities gain an `avoid:` anti-term list (`PYLON039`), accepted plan contracts of provable kinds demand a `verified_by:` or `falsified_by:` proof pointer (`PYLON040`), and quirks gain `ai_authored_contributed:` and `volume_pressure:` closed-token fields validated by `review postmortem` (`PYLON041`). `pylon review ratchet` counts advisories per package and zone against a committed baseline (`manifests/ratchet.json`); rising counts block (`PYLON042`) and `--update` re-baselines after review. `pylon review rework` counts `fix:` and `refactor:` commits that touch paths a `feat:` commit changed, report-only. Review hardening: the ratchet excludes clock-driven advisories (stale packages, audit reaudit dates, plan branches) and fails closed on an unreadable manifest; rework orders fixes against the feat that made a path hot and skips unreadable projects with a warning; provable kinds cover `ts-export`, `js-export`, and `rust-item`; stop blocks and advisory lines render the fix line; unknown package filters exit 2. The feature guide documents the six capabilities as cards, and the shipped roadmap items are gone per the ship rule.

## 2026-11-19: Initial Public Release

- Extracted and generalized the standalone Pylons living-map-ledger and `pylon` Go CLI (`cli/`).
- Added `pylons.yaml` multi-project registry with `repo://` and `pylon://` URI schemes.
- Added seven language-agnostic core contract kinds (`file`, `glob`, `symbol`, `route`, `cli`, `event`, `schema`) plus opt-in built-in extensions (`go`, `rust`, `typescript`, `python`, `php`) and external `pylon-ext-<name>` JSON plugin support.
- Added `PYLON001`–`PYLON038` deterministic lint and collision rules with `FORCED` / `ADVISORY` grades and `human`, `json`, `sarif`, and `--stop-block` output.
- Added `tickets/` zone, `archive/` exclusions across CLI context/search/manifest commands, and `protocols/` CLI-consumed templates with compiled-in defaults (`pylon protocol`, `pylon reflect`).
- Added `meta/` documentation.
- Licensed as Apache-2.0

## 2026-11-22

- Self-update writes the staged product manifest, so a second hop compares against the hashes actually installed; identical content is skipped instead of rewritten, and the binary swap checks its own hash.
- Self-update rejects release-manifest keys that could escape the ledger (absolute paths, parent segments, drive forms), on both the staged and the installed side.
- Baseline keys keep path numbers literal, so renumbered targets are new debt instead of silent swaps; duplicate budget entries in a hand-edited baseline sum.
- Unknown doc types fall back to the union of known frontmatter keys, so a custom type no longer mass-fires unknown-key advisories on title or type.
- Secret scanning recognizes PGP private-key blocks and the JSON, ENV-suffixed, dash-key, and bearer assignment shapes; install records a replaced core.hooksPath and names the chain line when a foreign hook shares the gate.
- The lint usage line documents --update-baseline.
- Documentation pass: the feature guide carries the proof machinery (secret shapes, gate guard, strict frontmatter, readable baseline) and true command and flag dictionaries; the roadmap gains five deterministic retrieval items with a recall gate.
- Search ranks on situated documents: a deterministic header carries structured frontmatter fields into the index while YAML keys never score, and a fusion pass promotes live status, recent updates, exact rule ids, and the queried project over equally-scoring stale records. Query expansion resolves source-file and package tokens to their owning package and dependency-graph neighbors, surfaced in human output and as an explicit JSON field; the search index gains one-hop domain vocabulary from linked entities. Path queries resolve repo:// tokens, caller-cwd-relative paths, and ledger-relative paths, so expansion fires for any registered layout; the search --json output changed shape from a bare array to an object carrying expanded and docs, which is a breaking change for external consumers. The new `pylon harvest pr --diff <patch> [--metadata <json>]` turns a merged PR diff into a candidate patch: exported-symbol exposes proposals anchored to the claiming package doc, scaffolded quirk post-mortems for line-anchored `Footgun:` markers, and warnings for unattributed paths. The engine never writes to main; a maintainer applies the artifact by hand. With `--record`, harvest appends each `Footgun:` marker to a JSONL findings file, and the new `pylon review retro --findings <file|-> [--window <period>] [--min <n>] [--shape <s>]` counts signature repeats inside the window to open exactly one promotion candidate per signature: a convention stub in `conventions/proposals/`, a `wrong_if` entry for the named contract, or a lint-rule proposal, chosen by unanimous record shape with a convention default. A later review round hardened both commands: unstructured findings accumulate on a normalized-text slug so distinct footguns never share a signature, the diff parser is hunk-aware and survives tab-suffixed, CRLF, and quoted git paths, in-hunk +++ lines stay content, warnings render even when a diff yields no candidates, artifact text is sanitized, extraction covers Go generics and grouped const/var members plus modified rust and indented php declarations, the findings read cap widened to 64 MiB with pruning guidance, --min rejects zero, record shapes and falsifiers without a contract fail closed, and fixture dates no longer decay with the calendar.
