# Pylons Changelog

Notable changes to the Pylons format and `pylon` CLI.

## 2026-11-20

`pylon aroma` ships structural code similarity as a top-level subcommand: given changed lines, a snippet, or a diff, it finds the corpus methods whose code structurally resembles the query and returns the code they share, zero model calls, advisory only. The algorithm is the Aroma paper (OOPSLA 2019) ported from its reference implementation, pinned by differential goldens generated from that reference, with a stdlib-parser Go front end and a recall benchmark. The corpus defaults to the ledger's registered projects, else `--corpus`. Review hardening closed its findings batch: corpus roots are labeled so several projects cannot collide and every query input resolves inside its owning root, snippet, diff, and stdin reads run through one bounded regular-file reader, the Go front end stops reading selector fields, literal keys, and labels as locals, explicit flag zeros survive parsing, `--help` works after the subcommand, and an empty corpus exits 2, so the command never exits 1. Two more roadmap items shipped: `pylon review release-surface --pinned-releases <dir> [--base <ref>]` blocks when a pinned deployment consumes a public surface (symbol, route, or cli contracts) that is removed or changed against the pinned release tag, with unknown pins, missing tags, and unevaluated pins failing closed or advisory; and `pylon context --diff-since <ref> [--manifest]` reports declared surfaces the diff touched whose docs did not move in the same commit set, report-only, with the friction-scored quirk capture left to the agent harness per the not-adopted list.

Roadmap build-out, round 2. `pylon lint` gains `PYLON043`: files inside a registered project that import another registered project not declared in the owning package's `depends_on:` fire an advisory, backed by import extraction for go, typescript, python, rust, and php. `pylon check` names the ripple: plans and packages declaring the same contract id, quirks anchored to the same file, and domain terms named in the source (`PYLON044`). Plans gain the opt-in vertical-slice flavor: `slice: true` demands a behavior contract and a test surface (`PYLON045`), and declared `scenarios:` with `covers:` prove behavior contracts (`PYLON046`). `pylon context --slice <plan>` prints only that slice's contracts, resolved surfaces, linked quirks, and domain terms. `pylon protocol agent` ships the canonical agent session loop as a compiled protocol beside `reflect`. Same day: import-boundary matching hardened (alias-vs-package ownership, longest-prefix identity match, collision and nested-root ambiguity skipped, go parsed with the stdlib parser, python identities only for real packages, per-target dedupe, manifest reads lstat-bounded, `PYLON043` exempt from the ratchet budget); ripple gained glob-contract matching, a package-status filter, and real KB-doc anchors; slice rules gate on accepted/in-progress plans only and treat a covers-only scenario as no coverage; a plan document whose frontmatter cannot parse now fails loudly instead of silently skipping its rules. Two more roadmap items shipped: `pylon review merge-danger --body <file|-> [--base <ref>]` gates the required `Merge danger: <one-way|two-way> | blast radius: <scope>` body line (conventions/pr-template.md) against the closed door vocabulary and derives the minimum door from schema contract changes in the diff, blocking any downgrade; and `pylon sync --detached` runs a detached background fetch when the last one is over an hour old, applies fast-forward-only updates on a clean tree, records the fetch state in `.git/pylon-sync.json`, and surfaces `FETCH-FAILED <time>` through `brief`; the fetch state race, git worktree state paths, and the fast-forward guard (main only, strict ancestor) closed in the same pass. Two more shipped the same day: `pylon context --graph <package> [--depth N]` reports declared `depends_on` against the actual import edges the import-boundary extractor finds across registered projects, marking undeclared edges and unused dependencies, report-only; and `pylon review annotations --from <file|->` converts lint findings (SARIF or JSON) into GitHub Check annotations plus a summary comment body, blocking errors only and capped at 50, so the CI workflow posts inline PR feedback from pylon output. A third shipped the same pass: `pylon lint --parity` runs opt-in declared-vs-code set checks, comparing a domain entity's `states:` list against the backed enum at its `states_symbol` pointer (backing values when every case carries a literal, else case identifiers) with count and state mismatch as errors and an unresolvable enum failing closed as an advisory, plus route exposes checked against mentions in the mapped project source as an advisory. A peer review closed the same day hardened the extractors: blocks are found by delimiter matching so a later block in the same file is reachable, a case line the extractor cannot read fails closed as an advisory, trailing comments and single-quoted values parse, and `--parity` with `--doc-only` warns instead of silently doing nothing.

Hardening round. Project matching is deterministic for nested registered roots. Config errors surface instead of silently degrading output. All git subprocesses run under a 10-second budget. Symbol contracts match on word boundaries. Contracts whose components do not map to a registered project now fail instead of skipping. A configured git ref that does not resolve fails closed instead of falling back to the working tree. `pylon install` refuses a pylon below the repository root, detects another tool's `core.hooksPath` (override with `--force`), and reports hooks that drifted from the shipped assets. Gate hooks fail closed when no `pylon` binary is found; `PYLON_HOOKS_OPTIONAL=1` restores the old soft skip. `staleness --fix` patches frontmatter only. SARIF is rejected on commands that cannot render it; `pylon brief` without a pylon root exits 3. A one-line installer (`install.sh`) downloads a release into a project as a fresh pylon with its own git repository, verifies checksums, and wires the gate hooks; releases carry optimized per-platform binaries (`-s -w`, `CGO_ENABLED=0`, `-trimpath`) plus the skeleton and checksums, and `pylon --version` reports the release. The installed unit is now called a pylon: a plain-text map of the platform with a deterministic checker, replacing the working term knowledge base.

Roadmap build-out. Every lint finding now carries a remediation line sourced from the rule catalog (human, json, and sarif). Domain entities gain an `avoid:` anti-term list (`PYLON039`), accepted plan contracts of provable kinds demand a `verified_by:` or `falsified_by:` proof pointer (`PYLON040`), and quirks gain `ai_authored_contributed:` and `volume_pressure:` closed-token fields validated by `review postmortem` (`PYLON041`). `pylon review ratchet` counts advisories per package and zone against a committed baseline (`manifests/ratchet.json`); rising counts block (`PYLON042`) and `--update` re-baselines after review. `pylon review rework` counts `fix:` and `refactor:` commits that touch paths a `feat:` commit changed, report-only. Review hardening: the ratchet excludes clock-driven advisories (stale packages, audit reaudit dates, plan branches) and fails closed on an unreadable manifest; rework orders fixes against the feat that made a path hot and skips unreadable projects with a warning; provable kinds cover `ts-export`, `js-export`, and `rust-item`; stop blocks and advisory lines render the fix line; unknown package filters exit 2. The feature guide documents the six capabilities as cards, and the shipped roadmap items are gone per the ship rule.

## 2026-11-19: Initial Public Release

- Extracted and generalized the standalone Pylons living-map-ledger and `pylon` Go CLI (`cli/`).
- Added `pylons.yaml` multi-project registry with `repo://` and `pylon://` URI schemes.
- Added seven language-agnostic core contract kinds (`file`, `glob`, `symbol`, `route`, `cli`, `event`, `schema`) plus opt-in built-in extensions (`go`, `rust`, `typescript`, `python`, `php`) and external `pylon-ext-<name>` JSON plugin support.
- Added `PYLON001`–`PYLON038` deterministic lint and collision rules with `FORCED` / `ADVISORY` grades and `human`, `json`, `sarif`, and `--stop-block` output.
- Added `tickets/` zone, `archive/` exclusions across CLI context/search/manifest commands, and `protocols/` CLI-consumed templates with compiled-in defaults (`pylon protocol`, `pylon reflect`).
- Added `meta/` documentation.
- Licensed as Apache-2.0

## 2026-01-26: Origin

- Initial design of the living-map-ledger model, typed contracts, controlled language (ASD-STE100), and deterministic CLI verification loop.
